# OmniVoice-Studio Setup Guide

**Status**: Docker build in progress (as of 2026-04-19 07:52 UTC)

## Service Overview

- **Name**: OmniVoice Studio
- **Type**: Docker container (Python + PyTorch)
- **Port**: 8051 (remapped from Docker :8000)
- **Features**: Cinematic video dubbing — transcribe → translate → re-voice → mux with stem separation, timeline editor
- **GPU**: Requires NVIDIA CUDA 12.1+
- **Models**: ~1.2GB HuggingFace models (OmniVoice zero-shot TTS)
- **Launch**: `bash /srv/containers/edq/scripts/start_omnivoice_studio.sh`
- **Stop**: `docker compose -f /srv/containers/edq/docker/omnivoice-studio/docker-compose.yml down`

## Build Issues & Fixes (Critical for Future Rebuilds)

### Issue #1: Missing frontend/bun.lock

**Problem**: Dockerfile expected `COPY frontend/bun.lock ./` but file didn't exist in repo.

**Root cause**: Frontend lockfile is generated by `bun install`, not version-controlled. Repo only contains root-level `bun.lock`.

**Fix**: Patched Dockerfile to remove `--frozen-lockfile` flag from `RUN bun install`, allowing Docker to regenerate:

```dockerfile
# Before:
RUN bun install --frozen-lockfile

# After:
RUN bun install
```

**Why this works**: When frozen-lockfile is omitted, bun can regenerate the lockfile inside the container without requiring a pre-existing one.

---

### Issue #2: Docker buildkit node_modules conflict

**Problem**: Build failed with: `ERROR: cannot replace to directory /var/lib/docker/buildkit/... with file`

**Root cause**:

1. Dockerfile runs `RUN bun install` which creates `/app/frontend/node_modules` inside the image
2. Later `COPY frontend/ ./` attempts to copy local `frontend/` directory (which includes local `node_modules`) into `/app/frontend/`
3. Docker buildkit's overlay fs conflicts when trying to overwrite a directory that was just created

**Fix**: Clean local node_modules before build:

```bash
rm -rf /srv/containers/edq/projects/omnivoice-studio/frontend/node_modules
docker compose -f docker/omnivoice-studio/docker-compose.yml up -d
```

**Why this works**: With no local node_modules, COPY only copies source files. Buildkit doesn't try to replace an in-image directory with a host directory.

---

### Issue #3: Missing README.md in pyproject.toml

**Problem**: Build failed during `uv pip install -e .` with: `OSError: Readme file does not exist: README.md`

**Root cause**: `pyproject.toml` references `readme = "README.md"`, but Dockerfile hadn't copied README.md before running install. Hatchling (build backend) validates metadata and fails on missing files.

**Fix**: Copy README.md before install step:

```dockerfile
# Before:
COPY pyproject.toml uv.lock ./

# After:
COPY pyproject.toml uv.lock README.md ./
```

**Why this works**: Hatchling validates pyproject.toml metadata at install time, so all referenced files must exist in the image before `pip install`.

## Build Checklist

Before running `docker compose ... up -d`:

- [ ] Ensure no local node_modules: `rm -rf projects/omnivoice-studio/frontend/node_modules`
- [ ] Verify README.md exists: `ls projects/omnivoice-studio/README.md`
- [ ] Verify Dockerfile has frozen-lockfile removed (line 11 should be `RUN bun install` only)
- [ ] Verify Dockerfile copies README.md (line 40 should include `README.md`)
- [ ] Create output directory: `mkdir -p ~/ai_generated/omnivoice_studio`
- [ ] Create HF cache symlink: `mkdir -p /srv/containers/edq/cache_huggingface`

## Testing Workflow

1. **Upload test video**: ~30-60 second clip
2. **Provide transcription**: Auto-detected or user-provided
3. **Select target language**: Spanish, French, German, Chinese, etc.
4. **Select voice**: Pre-trained voice or upload custom voice sample
5. **Export**: Muxed video with original stems + dubbed audio
6. **Timeline editing**: Adjust timing and re-voice specific segments
7. **Output**: Save to ~/ai_generated/omnivoice_studio/{timestamp}/

## Known Limitations

- **VRAM**: Requires 4GB+ for reliable operation
- **Model downloads**: First run downloads ~1.2GB from HuggingFace
- **Languages**: 600+ supported via OmniVoice model (check docs for exact list)
- **Concurrent jobs**: Run one at a time (check `nvidia-smi` before starting second job)
